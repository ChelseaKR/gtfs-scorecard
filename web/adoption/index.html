The newer, optional parts of GTFS

Accessibility data coverage

Cross-feed accessibility coverage is unavailable until current-contract checks create a comparable feed-record cohort. This snapshot makes no corpus-wide completeness or named-feed claim. What this measures: whether feeds publish the data, never whether a stop is physically usable.

Coverage is the share of a feed's stops carrying wheelchair_boarding and trips carrying wheelchair_accessible, the portable GTFS accessibility fields used by trip planners. California's Transit Data Guidelines are one regional source for this published scoring profile, not its worldwide authority. It never changes a grade. The same data is at the accessibility API (accessibility.json). This page is about data completeness; for how this site itself meets WCAG, see Accessibility. The directory contains 1128 published feed records. No cross-feed denominator is published for this snapshot.

In plain words: a feed does not need any of these to earn a good grade. This tracks where the newer, optional parts of GTFS are catching on, so an agency can see what peers publish and a program can see where to help next.

Adoption is read from each feed's own files: GTFS-Flex (locations.geojson, booking_rules.txt), fare data (fare_attributes.txt for the legacy model, fare_products.txt and fare_leg_rules.txt for Fares v2), and GTFS-Pathways (pathways.txt, levels.txt). It never changes a grade. The same data is at the adoption API (adoption.json). The directory contains 1128 published feed records. No cross-feed denominator is published for this snapshot.
